# 职教智能体教学实训平台：技术文档

本文档以当前代码为准，说明项目的目录结构、模块边界、现有数据模型、接口和后续开发规范。

## 1. 项目定位

平台面向职业教育场景，将产业链、岗位采集数据和 AI 分析结果组织成岗位能力图谱，并为后续的课程负责人分配、课程资源、教学安排和学习档案提供数据基础。

当前已具备的主流程：

```text
产业链 → 岗位 → 招聘数据采集 → AI 生成能力图谱 → 岗位能力树
```

后续业务流程：

```text
岗位能力树 → 选择学院/课程负责人 → 课程能力映射 → 教学资源与教学任务 → 学生学习档案
```

## 2. 技术栈

| 层级 | 方案 |
| --- | --- |
| 后端 | Django 5.x / Python |
| 数据库 | SQLite（当前开发环境） |
| 前端 | 原生 HTML、CSS、JavaScript、Web Component |
| AI | DeepSeek OpenAI 兼容接口，由 `ai/` 统一封装 |
| 异步任务 | 当前为 Python 后台线程；生产环境建议迁移至 Celery + Redis |

## 5. 分层约定

每个业务 app 后续遵循下面的职责划分：

```text
app/
├─ models.py       # 数据实体和约束
├─ urls.py         # 本模块 URL
├─ views.py        # 请求参数、调用业务逻辑、返回 HTML/JSON
├─ services.py     # 新增、编辑、删除、状态流转等写操作
├─ selectors.py    # 列表、详情、统计等查询组合
├─ permissions.py  # 权限规则（需要时新增）
├─ tasks.py        # 耗时任务（需要时新增）
├─ admin.py
├─ migrations/
└─ tests.py
```

规则：

1. 新数据实体先加在所属 app 的 `models.py`，再执行迁移。
2. `views.py` 不直接堆放复杂业务逻辑；写操作进入 `services.py`，复杂查询进入 `selectors.py`。
3. `config/urls.py` 只能通过 `include()` 汇总路由，不新增具体业务接口。
4. AI 调用只能经过 `ai/services.py`，业务视图不直接连接模型服务。
5. 跨 app 的业务协作优先使用外键、service 或明确的查询函数，不复制其他 app 的视图代码。

## 6. 数据模型

### 6.1 产业链与岗位

`apps.industry.models.Chain`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | CharField(100)，唯一 | 产业链名称 |
| `description` | CharField(500) | 描述 |
| `is_enabled` | BooleanField | 启用/禁用 |
| `created_at` | DateTimeField | 创建时间 |

`apps.industry.models.Job`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `chain` | ForeignKey → Chain | 所属产业链 |
| `name` | CharField(100) | 岗位名称；同一产业链内唯一 |
| `aliases` | JSONField | 岗位别名 |
| `search_keywords` | JSONField | 采集关键词 |
| `is_confirmed` | BooleanField | 是否人工确认 |
| `is_enabled` | BooleanField | 启用/禁用 |

### 6.2 招聘采集

`CrawlTask` 记录某岗位的一次采集任务，状态为 `pending`、`running`、`completed`、`failed`。

`JobListing` 保存每一条招聘信息，包括职位、公司、地点、薪资、学历、任职要求、人数、发布日期和来源。

### 6.3 能力图谱

`AbilityMap` 与岗位一对一，主要字段：

| 字段 | 说明 |
| --- | --- |
| `abilities_json` | 岗位能力树 JSON |
| `total_abilities` | 岗位能力数 |
| `total_skills` | 知识点/技能点总数 |
| `raw_text` | AI 原始返回文本，方便追溯 |
| `generation_status` | `ready`、`processing`、`error` |
| `generation_error` | 生成失败原因 |

当前树结构：

```json
[
  {
    "name": "机器人本体调试",
    "college": "智能制造学院",
    "enabled": true,
    "units": [
      {
        "name": "能力单元名称",
        "enabled": true,
        "children": [
          {"name": "可考核的知识点或技能点", "enabled": true}
        ]
      }
    ]
  }
]
```

禁用产业链、岗位、岗位能力或能力单元时，系统会递归禁用其所有子节点。知识点/技能点是叶子节点，不允许继续新增子节点。

### 6.4 迁移兼容

代码包已迁移到 `apps.industry`、`apps.collection`、`apps.capabilities`，但 Django 内部 app 标签仍保留 `chain`、`crawl`、`ability`，因此已有 SQLite 表与迁移记录无需重建。

新代码必须使用：

```python
from apps.industry.models import Chain, Job
from apps.collection.models import CrawlTask, JobListing
from apps.capabilities.models import AbilityMap
```

不要再使用旧的 `chain.models`、`crawl.models` 或 `ability.models` 导入路径。

## 7. 路由与 API

所有路由由 `config/urls.py` 汇总，并分散定义在每个 app 的 `urls.py` 中。

### 7.1 认证

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/login` | Session 登录 |
| POST | `/api/auth/logout` | 退出登录 |
| GET | `/api/auth/me` | 当前登录用户 |

### 7.2 产业链和岗位

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/chain/list` | 获取产业链及岗位数量 |
| POST | `/api/chain/create` | 新增产业链，并由 AI 生成岗位 |
| GET | `/api/chain/<chain_id>/detail` | 获取产业链和岗位列表 |
| DELETE | `/api/chain/<chain_id>/delete` | 删除产业链及下属岗位 |
| POST | `/api/job/create` | 手动新增岗位；同产业链禁止重名 |
| POST | `/api/job/<job_id>/update` | 编辑岗位别名、关键词、确认状态等 |
| DELETE | `/api/job/<job_id>/delete` | 删除岗位 |

### 7.3 采集

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/crawl/start` | 启动岗位招聘数据采集 |
| GET | `/api/crawl/<task_id>/status` | 查询采集进度与结果数 |

### 7.4 能力图谱

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/ability/generate` | 基于已完成采集数据异步生成图谱 |
| GET | `/api/ability/<job_id>/tree` | 获取能力树及生成状态 |
| GET | `/api/ability/<job_id>/text` | 获取 AI 原始输出 |
| POST | `/api/ability/node/toggle` | 启用或禁用一个节点；父节点禁用会级联子节点 |
| POST | `/api/ability/node/add` | 增加一个能力、能力单元或知识点/技能点；同级禁止重名 |

## 8. AI 处理流程

```text
创建产业链
  → ai.services.generate_jobs()
  → ai.jobs.gen_jobs()
  → ai.client.call_assistant()
  → 保存 Job

完成岗位采集
  → ai.services.generate_capability_map()
  → ai.capability_generation.gen_ability()
  → parse_abilities_to_tree()
  → 统计有效招聘要求（少于 10 条则标记为数据不足并停止）
  → 保存 AbilityMap
```

AI 返回异常时，能力图谱的 `generation_status` 设为 `error`，错误内容存入 `generation_error`，前端可以显示失败原因并允许用户重新生成。

AI 密钥应通过环境变量配置，禁止在文档、前端或 Git 仓库中写入真实密钥。

能力图谱生成前会先筛选任职要求长度超过 10 个字符的有效招聘记录：0 条或 1～9 条时不调用 AI，页面显示“数据不足，暂不生成图谱”；达到 10 条后才允许生成，达到 30 条时标记为数据较充分。

当前默认使用 DeepSeek：复制 `education_platform/.env.example` 为 `education_platform/.env`，填写 `DEEPSEEK_API_KEY`。岗位生成和能力图谱生成都会通过 `ai/client.py` 调用 `deepseek-chat`，不再需要讯飞的 APPID、APISecret 或助手 ID。

## 9. 前端结构

- `templates/index.html`：主框架，包含侧边栏和 iframe 内容区域。
- `templates/能力图谱库.html`：产业链、岗位、能力图谱树及节点操作。
- `static/components/sidebar-menu.js`：侧边栏 Web Component。

能力图谱页面在新增、切换节点状态后会重新拉取局部数据，并保存已展开节点的状态，避免用户手动刷新页面后回到首页或丢失当前浏览位置。

## 11. 后续开发顺序

1. 在 `organizations` 新增学院、专业、班级、教师模型，并将岗位能力的学院选项改为数据库查询。

5. 使用 `notifications` 记录下发通知、审核结果与关键操作日志。
6. 使用 Celery + Redis 替换后台线程，提升 AI 与采集任务的可靠性、可追踪性和并发能力。
